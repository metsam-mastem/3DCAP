# Capture Passport — Data Contract

**Passport schema:** 1  
**Capture Manifest schema:** 1  
**Encoding:** UTF-8 JSON  
**Archive:** ZIP

## 1. Archive layout

    passport.json
    passport-report.txt
    manifest.json
    COLMAP_IMPORT.txt
    images/
      <registered-capture-image>.jpg

A top-level directory may be omitted to preserve the current exporter convention. Entry names must be relative and must not contain absolute paths, drive prefixes, parent traversal or duplicate names.

## 3. Field rules

- schema_version: positive integer; unsupported major versions are not interpreted as current.
- passport_id: stable for the session/schema identity and contains no user identity.
- generated_at: ISO-8601 UTC instant.
- session_id must equal the Capture Manifest session ID.
- frame_count must equal manifest frame count.
- readiness: INSUFFICIENT, REVIEW or READY.
- coverage percent: integer 0–100.
- missing_cells: unique normalized yaw/pitch pairs from the configured plan.
- checks: stable IDs and explicit outcomes/severity.
- evidence: bounded scalar/array values; no image bytes or unrestricted paths.
- limitations: mandatory where check semantics could be misinterpreted.

## 4. Consistency invariants

Reject unsupported schema, invalid identity, session/count mismatch, invalid enums, out-of-range percentages, negative counts, covered > total, duplicate missing cells, malformed timestamps, unsafe paths, and unknown outcomes interpreted as positive.

Readers may ignore unknown additive fields and must display unknown checks as unrecognized rather than assuming PASS.

## 5. Integrity evidence

Manifest stores expected byte size and SHA-256. ZIP writer streams each file, counts bytes and hashes while copying. It compares both to manifest before finalizing. A mismatch fails export and no completed Passport ZIP is published.

image_file_integrity is PASS only after all image bytes are streamed and validated; FAIL on mismatch; NOT_MEASURED before export-time verification. Do not duplicate full hashes in every check; reference the manifest frame.

## 6. Human-readable report

passport-report.txt is generated from the same immutable Passport object as passport.json. It contains identity/time, exact readiness meaning, coverage/missing targets, checks/evidence/limitations, unmeasured properties, inventory count, schema and analyzer versions. It must not recalculate values independently.

## 7. ZIP/import security

Generate entries only from registered frame names. Reject parent traversal, absolute paths, backslashes with path semantics, drive paths, NUL and duplicate entries. Importers must defend against ZIP Slip, oversized entries, excessive entry count and decompression bombs. Bound JSON size, list lengths and strings.

Hashes are integrity checks, not signatures. Passport is not signed and does not establish who captured the object.

## 8. Versioning

Additive optional fields: same schema. Breaking shape/required field/enum semantics: increment schema. Analyzer algorithm changes that alter outcomes: increment analyzer version. Never silently re-label old Passports as if generated by a new analyzer.
